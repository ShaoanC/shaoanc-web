## 备份内容与使用

管理员进入“设置 → 数据备份”，可立即创建全站备份，或开启自动备份。备份包含账号、错题、知识点、复习记录、回收站、业务图片，以及存在的 `.env` 和 `.env.ai`。备份含密码摘要、配置和服务密钥，请保存在可信位置。未保存的浏览器草稿、程序依赖和缓存不在其中。

默认备份目录为项目的 `data/backups/`，可用 `MISTAKES_BACKUPS_PATH` 指定静态目录之外的位置；目录需要服务账号可读写。备份仅对管理员开放，不通过静态服务器提供。下载包为 `.tar.gz`，可以从设置中下载到其他设备；本机副本不能覆盖服务器磁盘损坏的风险。

自动备份默认关闭。开启后默认每天北京时间 03:00 执行，保留最近 7 份自动备份；成功创建新包后才清理旧包。手动备份和恢复前回退包由管理员手动删除。停服期间错过的时间不补跑；撞上已有备份时跳过。页面会显示最近执行结果和下次执行时间。

创建时暂停新写入和后台调度，等待正在执行的 AI 与裁图完成，再保存 SQLite 一致性快照、图片和配置。该阶段仍可浏览，保存和上传提示稍后重试，输入内容保留。复制完成后恢复使用，压缩在后台继续。失败会解除只读，旧备份继续保留；进程重启后，未完成的任务显示为已中断。

## 停服恢复

使用与创建备份相同版本的应用代码和依赖。先停止 Node 服务，在目标部署中准备好 `.env`，其中数据库、图片、AI 配置和备份目录采用目标服务器的路径，再执行：

```powershell
npm run backup:restore -- "备份文件的绝对路径.tar.gz" --confirm
npm start
```

命令检测服务运行时拒绝恢复。首先在临时目录解包并检查清单、路径和数据库；通过后为当前数据创建恢复前回退包，再成套替换数据库、图片和配置。替换失败会回滚已替换的内容。旧数据库 WAL/SHM 不与恢复后的数据库混用。

恢复后的环境文件保留目标部署的数据目录路径，其他配置从包内恢复。源备份缺失的配置会按清单处理，不混入旧 AI 配置。进程环境中临时注入的变量不在备份内，需要由部署环境重新提供。

自动备份设置与任务历史保存在备份目录的 `state.json`，重启后保留；恢复数据时保留目标服务器现有的备份设置和历史，新服务器默认关闭自动备份。归档不包含其他备份包和备份历史，避免重复嵌套。

恢复后所有账号重新登录。备份时未完成的 AI、分题与裁图任务不会自动重放，可在对应页面手动重试，避免恢复时再次发起收费请求。恢复前回退包保留在备份目录；需要撤销时，停服后用同一命令恢复该包。

## 接口

所有管理接口都要求管理员会话，返回现有 `{ success, data }` 格式并禁止缓存。

| 接口 | 用途 |
| --- | --- |
| `GET /api/mistakes/admin/backups` | 历史备份、当前任务和只读状态 |
| `POST /api/mistakes/admin/backups` | 创建后台任务，返回 202 |
| `GET/PATCH /api/mistakes/admin/backups/settings` | 自动备份设置、最近结果和下次时间 |
| `GET /api/mistakes/admin/backups/:id/download` | 下载完成的归档 |
| `DELETE /api/mistakes/admin/backups/:id` | 删除备份和历史记录 |
| `GET /api/mistakes/system/status` | 已登录用户查询只读状态 |

只读期间写请求返回 `503` 和 `BACKUP_READ_ONLY`，重复创建备份返回 `409`。
