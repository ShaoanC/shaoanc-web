```powershell
npm run baseline:ai -- data/photo-baseline/manifest.json before --check
npm run baseline:ai -- data/photo-baseline/manifest.json before
npm run baseline:ai -- data/photo-baseline/manifest.json after
npm run baseline:ai -- --compare data/ai-baseline-before-时间戳.json data/ai-baseline-after-时间戳.json
```

`--check` 仅检查清单及图片，不调用模型。正式评测使用现有 `.env.ai`（也支持 `MISTAKES_AI_CONFIG_PATH`），每例请求一次且不自动重试；会产生服务商的实际调用费用。脚本共用生产识别提示词和请求逻辑，使用隔离的临时数据库，不创建或修改业务错题。JSON/Markdown 报告写到忽略 Git 的 `data/`，记录图片 SHA-256/宽高、提示词指纹、模型、原始结果、错误类别、耗时、调用次数和 token 用量。失败案例仍保留在报告内，进程退出码为 1。用量缺失为 null。

在前后两份 JSON 的每例 `review` 中人工填写 `criticalContentErrors`（关键条件/公式错误数）、`figureComplete`（图形与标注是否完整）、`handwritingLeak`（是否混入应剔除作答）、`manualEdits`（按同一口径记录人工修改次数）及 `notes`，再运行比较命令生成 `comparison.md`。未评分仍显示“待人工评分”；比较会提示图片内容变化。模型耗时不包含浏览器预处理，后者单独计时。正式基线应在改动前后各跑一遍，保持模型、服务及原题来源一致。

### 编码与请求策略

旋转和裁剪均通过浏览器原生 `canvas.toBlob('image/png')` 保留中间像素；不使用压缩库会做调色板量化的 PNG 导出。PNG 在最长边 2560 内先以 `.88` 质量编码 JPEG，超过 1.5MB 才交给现有压缩器继续压缩，避免压缩库按较小 PNG 文件大小强制降质。其他原始图片仍沿用现有压缩器，服务器上传类型及 4MB 上限保持不变。

题干提示词按“忠实转写 → 区分原题与作答 → 保留图形 → 建议归类”组织；答案采用前三项，同次请求、结果结构及自动填入规则保持不变。每张图片另附从实际发送 JPEG 读取的宽高；选框仍以该图归一化。格式错误在累计第 2 次及以后停止重试，截断立即失败并提示减少图片；网络、429、5xx 等保持原有三次尝试预算。重启沿用已消耗次数，手动重试重新计算。

请求日志为 JSON 事件 `mistakes.ai.request`，包含模型、任务类型/编号/尝试次数、图片数量、`elapsedMs`、`status`、`errorCategory`、`usage`。错误类别包括 `format`、`truncated`、`vision_mismatch`、`rate_limit`、`authentication`、`timeout`、`cancelled`、`http_状态码`、`network`。不记录题目、图片数据、接口地址或密钥。图片测试通过只证明固定测试图可读取，真实题图效果仍需上述基线验收。

## 使用

1. 管理员进入“设置 → AI 设置”，填写 Gemini 原生 API 基础地址（官方为 `https://generativelanguage.googleapis.com/v1beta`，也可用兼容原生协议的代理）、API 密钥和支持图片输入的 Gemini 模型名称，启用并保存；不要填写完整 `generateContent` 路径。旧版 OpenAI 兼容地址需按本页迁移说明更新。密钥不回传浏览器，留空可保留已有密钥。“测试图片识别”发送固定测试图并核对图中文字；请求失败与请求连通但未正确读取会分别提示。
2. 进入“录入错题”，拍照或选择 JPG、PNG、WebP 图片。同一道题每次可选 1–12 张，逐张调整矩形选区，可追加、移除、调整顺序，上传前可左右旋转 90°。旋转会重置当前选框并清除该图上传缓存，显示方向与上传方向一致；不去除彩色笔迹。
3. 点击“上传并识别题目”。上传前自动创建/保存草稿，旋转及裁剪使用无损 PNG 中间图，最终整图与裁剪图均在客户端压缩为 JPEG（最长边 2560，目标不超过 1.5 MB），再备份到服务器；模型只接收选中的裁剪图。
4. 无疑点、无配图、目标为空且内容仍匹配提交快照时，自动填入识别文字与归类。存在疑点、配图或冲突时，点击“校对并填入”：桌面并排查看来源裁剪图和可编辑结果，手机切换“图片／结果”；可预览公式和表格、调整学科及知识点。归类无法确定时允许暂缺，不丢弃转写文字。
5. AI 一次请求同时转写和定位图形，一张图片可有多个编号选框，坐标以发送给 AI 的裁剪图为基准。有效区域默认选中，可拖动、缩放、删除或补画，并编辑说明。先在文字中放置光标，再点“插入配图”确定位置；没有光标时追加到末尾。删除区域会同步移除对应标记。无效坐标只提示校对，不自动裁图；悬空的配图标记必须补画或明确移除后才能填入。
6. 确认后按最终选框生成独立 JPEG，复用图片上传接口保存，再将标记替换为本站图片地址。预览与填入使用同一份文字和配图顺序。上传中断会保留文字和选框，重试复用上传编号，所有必要配图上传成功后才应用结果。裁剪只改变范围，作答与必要标注重叠时应检查，可保留原样。
7. 答案可以直接输入，也可以拍照或选择多张图片识别。两种入口使用同一个答案字段；已有答案时可校对后替换或追加。校对期间修改了题目内容，校对稿继续保留；冲突检查通过或明确选择替换后才覆盖。
8. 编辑页与详情页的“查看上传图片”保留整图及裁剪图，可放大。编辑页还能重新裁剪、选择历史图片重新识别；历史列表有可见序号和前后移动按钮，按显示顺序提交。
9. 顶部“AI 任务”集中查看排队、处理中、等待重试、识别完成待校对、已填入、失败、取消状态，以及用时、尝试次数和原始结果。图片上传完成后，离开页面或关闭浏览器也不会中断服务器 AI 任务。失败可手动重试，或回到编辑页补充图片/文字后重新提交。

## 识别协议

题干识别只发送裁剪图、学科列表及当前用户可见知识点目录；答案识别只发送图片与转写要求。已有内容快照保留在任务中用于冲突检查，不发送给识别模型。多图按提交顺序读取，重复部分去重，保留题号、条件、选项、公式和原题标注，排除学生作答和订正；模糊内容用 `[待确认]`／`[待补充]` 表示，不猜测补全。

模型识别结果的配图使用 `imageIndex` 和 Gemini `box_2d: [ymin, xmin, ymax, xmax]`（0–1000），服务端归一化后返回 `issues: [{ imageId, type, description }]` 和 `figures: [{ id, imageId, box, description }]`。`imageId` 是本次提交的图片数据库编号；`id` 是任务内唯一配图标识，正文使用 `[[figure:标识]]` 放置。客户端 `box` 为 `[left,top,width,height]`，以实际发送裁剪图的宽高归一化到 0–1，无效时保留为校对提示。几何图、函数图、电路图和示意图保留截图与必要标注；简单表格转 Markdown，复杂或数据不清的表格返回截图区域并提示校对。

`needsReview` 由服务端依据问题列表、待确认／待补充标记、配图区域和未匹配标记推导。新结果不会自动追加整张识别图片。旧任务的 `diagramImageIds` 仍可读取，对应裁剪图作为全图选框进入校对，可重新调整；原始结果单独保留供查看。

## 自动解析与编辑保护

短答案由代码判断：提取 Markdown 正文后不超过 80 个非空白字符，原答案不超过 3 个非空行（独占一行的 `$$` 不计）。同时要求题干、答案非空且解析为空。

手动答案在点击保存时判断；OCR 答案在填入后判断，先识别答案后识别题干也能触发。长答案默认不生成，用户可主动点击“生成解析”。待校对结果不会自动应用；题干或答案仍有待确认／待补充标记时不自动解析，补全保存后恢复现有触发规则。同一自动任务输入按文字及配图指纹去重，失败任务可在任务中心手动重试。

解析会提取题干与答案中引用的本站图片，验证属于当前用户和当前错题后，与文字一起发给模型；不读取外部图片。题干、答案合计最多 12 张，超限时提示精简。

结果先保存到数据库。题干/答案识别由编辑器在本地字段仍匹配快照且目标为空时自动填入；有冲突时保留候选。自动解析只有数据库中的题干、答案及解析仍匹配提交快照时才写入。编辑器只保存用户改动的字段，避免把后台生成结果覆盖为空；用户在等待期间的本地修改也会保留。已有解析时，主动生成的结果仍需用户选择替换。

## 知识点与隔离

共享知识点由管理员维护；所有账号可维护自己的个人知识点。AI 优先复用当前账号可见目录，不足时建立个人分支，可以挂在共享节点下。只有应用题干结果时才创建新节点，不会因未采用的结果污染目录。其他账号不可读取、修改或引用这些个人节点。

图片和任务均绑定错题及用户，访问须登录。派生配图使用题干用途并记录可空的 `source_image_id`；应用时校验引用属于本次任务来源图片或其派生配图。移入回收站时取消正在运行的任务，保留图片 30 天；恢复错题后仍可查看。永久删除或回收站到期清理时，同时删除来源图、派生配图和任务记录。

## 实现与部署

- 裁剪使用 `react-image-crop`；压缩使用 `browser-image-compression`，Worker 资源随构建本地发布。
- 上传使用 `multer`，每份整图/裁剪图上限 4 MB；上传编号支持失败重试去重。
- AI 请求使用 Node.js 内建 `fetch` 调用 Gemini 原生 REST 接口，数据结构使用 `zod`，队列与重试使用 `p-queue` / `p-retry`。现有 `react-markdown`、KaTeX、Base UI 与 `react-toastify` 用于富文本、弹窗和反馈。
- 单个 Node 进程内并发 2 个 AI 任务；每次请求超时 90 秒。网络等可恢复失败最多尝试 3 次，按 2 秒、4 秒退避，兼顾服务商 `Retry-After`（上限 120 秒）；格式错误最多尝试 2 次，输出截断及鉴权/不支持请求等错误直接失败。HTTP 请求不额外重试，避免次数叠加。
- SQLite 持久化任务、输入快照、结果、时间和尝试次数；重启后恢复未完成任务并保留已消耗次数。
- 上传和 AI 处理使用长驻 toast；完成提示保留 8 秒，失败提示保留到关闭，任务中心可再次查看与操作。
- 默认图片目录 `uploads/mistakes/`，可通过 `MISTAKES_UPLOADS_PATH` 调整。管理员配置存入忽略 Git 的 `.env.ai`，可通过 `MISTAKES_AI_CONFIG_PATH` 调整。数据库沿用 `MISTAKES_DB_PATH`。
- 部署时运行 `npm ci --cache ./data/.npm-cache`、`npm run build`，重启 Node。数据库结构在启动时自动升级，现有知识点保持共享。
- Nginx API location 建议设置 `client_max_body_size 10m`、`proxy_read_timeout 120s`。生产环境使用 HTTPS。
- 保留并备份 `data/`、图片目录和 `.env.ai`，不要随发布覆盖。图片“备份”指服务器持久保存压缩后的整图/裁剪图，不保留未经压缩的原始文件；异机备份由部署环境负责。

## 主要接口

前缀 `/api/mistakes`；JSON 保持 `{ success, data }`。

- `GET /ai/config`：普通用户仅能读取启用/配置状态。
- `GET/PATCH /admin/ai/config`、`POST /admin/ai/test`：管理员配置和连接测试。
- `POST/GET /mistakes/:id/images`：上传整图/裁剪图，读取历史。multipart 字段沿用 `original`、`crop`、`purpose`、`clientId`，增加可选 `sourceImageId`，派生图必须使用 `purpose=question`。
- `GET /images/:id/:variant`：鉴权读取 `original` / `crop`。
- `POST/GET /ai/jobs`、`GET /ai/jobs/:id`：提交和查看本人任务。
- `POST /ai/jobs/:id/retry`、`/cancel`、`/apply`：重试、取消、填入结果；`apply` 支持 `force` 明确替换、`mode: "append"` 追加答案、可选 `review` 校对文字与归类及 `expectedInput` 校对开始时的内容快照。未完成图片上传或仍有悬空标记时不能应用；新知识点只在应用成功时创建。
- 保存错题带 `generateAnalysis: true` 时触发短答案判断。

接口类型见 `client/mistakes/src/ai-types.ts`。
