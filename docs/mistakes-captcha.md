## 场景

每次登录（包括管理员）和邀请码注册需要人机验证。登录后修改密码、管理员重置用户密码及错题操作沿用现有认证流程。未来增加匿名找回密码时，在发送重置邮件或短信的入口接入验证。

## 接口与故障处理

- `GET /api/mistakes/auth/config` 返回 `{ enabled, sitekey }`，不公开 API Key，响应禁止缓存。配置仅在服务器启动时读取，修改 `.env` 后重启 Node。
- 登录和注册的 JSON 增加 `captchaResponse`。开启时，服务端先限流、检查基础参数，再向 Global v2 siteverify 核验，最后检查密码或邀请码、创建会话；不改数据库结构。
- 仅 `success === true` 视为核验成功。结果缺失、无效、过期和重复使用均拒绝。配置错误返回 `CAPTCHA_CONFIG`，不降级。
- 官方请求超时为 5 秒。连接失败、超时、429、5xx 时记录日志，登录继续检查密码及账号启停状态，注册返回 `CAPTCHA_UNAVAILABLE`。仅浏览器报错不触发放行。
- 前端收到组件错误时，登录可携带 SDK 错误响应提交，由服务器决定是否降级；注册保持禁用并提示重试。切换表单、过期和提交失败会清空旧结果；重试及切换时重建表单和验证码以恢复 iframe 加载，保留受控输入值，同时避免 SDK 残留 Focus 监听；组件卸载释放实例。

## 限流与部署

使用 `express-rate-limit` 默认内存存储，保持单 Node 进程。登录每 IP 每 15 分钟最多 60 次请求，同 IP＋用户名每 15 分钟最多 5 次失败；账号键按 SQLite NOCASE 行为统一 ASCII 大小写，成功登录和服务端 503 不占失败额度。注册每 IP 每小时最多 20 次请求。超限返回 429、`RATE_LIMITED` 与 `Retry-After`。

Express 仅信任回环代理。README 的同机 Nginx 配置使用 `$remote_addr` 覆盖 `X-Forwarded-For`，防止客户端自行指定限流来源。增加 CDN／代理层或多个 Node 进程时需调整真实 IP 或共享计数存储。

生产需提供 Friendly Captcha Sitekey 和服务器 API Key，在控制台配置实际域名、Global、Smart，设置 `FRIENDLY_CAPTCHA_ENABLED=true` 后重启。前端 SDK 从本网站加载，但浏览器仍需连接 Cloud。
